2. Единицы измерения в CSS

В проекте не используется единица ch (ширина символа «0»). Ниже — единицы, которые реально встречаются в screen.css и responsive.css.

ЕдиницаЧто этоГде в проекте
pxПиксели, фиксированный размерГраницы 1px, иконки 46×46px, скроллбар height: 3px, сетка каталога 270px / 320px
remОтносительно корневого font-size (обычно 16px)Отступы padding: 1.1rem, шрифты 0.86rem, gap в grid
emОтносительно font-size текущего элементаletter-spacing: 0.12em в подписях категорий
%Процент от родителяwidth: 100%, прогресс доставки, imageOffsetY: "0%" в данных
vh, vw% от высоты/ширины окнаmin-height: 100vh у body; calc(100vw - 1.4rem) у корзины на планшете
vminМеньшее из vh и vwclamp(252px, 87vmin, 450px) — логотип на мобильных
frДоля свободного места в CSS Gridgrid-template-columns: 270px minmax(0, 1fr) 320px
degГрадусы (градиенты, повороты)linear-gradient(135deg, …) в .page-glow
sСекунды (анимации)transition: transform 0.22s ease

Функции calc(), min(), max(), clamp(), minmax()

  • calc(100vw - 1.4rem) — ширина выезжающей корзины с отступом от края экрана (responsive.css, ~стр. 13).
  • min(360px, calc(100vw - 1.4rem)) — не шире 360px и не вылезает за экран.
  • clamp(252px, 87vmin, 450px) — логотип: минимум 252px, предпочтительно 87vmin, максимум 450px.
  • minmax(0, 1fr) — колонка сетки может сжиматься до 0, растёт на оставшееся место.
На защите: rem удобен для масштабирования всего интерфейса; px — для тонких линий и точных размеров; vw/vh — привязка к окну браузера; fr — только в Grid.

3. CSS-переменные (кастомные свойства)

В проекте две переменные задаются инлайн на каждой картинке товара и читаются в CSS.

js/app.js — при рендере карточки (строки 226–227):

<img ... style="--img-scale:${item.imageScale ?? 0.88}; --img-offset-y:${item.imageOffsetY ?? "0%"};">

css/screen.css — применение (строка 542):

transform: translateY(var(--img-offset-y, 0%)) scale(var(--img-scale, 0.88));

js/data.js — значения в объекте товара (пример, строка 29):

{ id: "tshirt-1", ..., imageScale: 0.84, imageOffsetY: "0%" }

Зачем: разные PNG по размеру визуально выровнять в одной карточке без отдельного класса на каждый товар. Второй аргумент в var(--img-scale, 0.88) — значение по умолчанию, если переменная не задана.

4. Представление данных: массивы и объекты

4.1. Справочники и каталог (data.js)

Данные вынесены в глобальные переменные на window, чтобы их видели и app.js, и admin.js.

js/data.js (строки 12–18, 28–29):

window.NOIR_STYLES = new Array(
    { id: "y2k", label: "Y2K" },
    ...
);
window.NOIR_BASE_PRODUCTS = new Array(
    { id: "tshirt-1", name: "...", category: "top", price: 1499,
      styles: new Array("punk", "grunge"), rating: 4.6, ... },
    ...
);
  • Массив — упорядоченный список элементов (стили, категории, товары).
  • Объект — одна сущность с полями: id, name, price, styles (массив id стилей).
  • new Array(...) — конструктор массива (в методичке ГУАП часто требуют именно так).

4.2. «Вектор» в контексте курсовой

В математике вектор — набор чисел. В вашем проекте ближайшие аналоги:

  • массив styles: ["punk", "grunge"] — список меток стилей;
  • массив cart — строки корзины { product, qty };
  • при построении графика Chart.js — массивы labels и values (категории и количество товаров).

Отдельного типа «Vector» в JavaScript нет — используются обычные массивы.

const stored = safeJsonParse(localStorage.getItem(PRODUCTS_STORAGE_KEY) || "");
if (!Array.isArray(stored)) return BASE_PRODUCTS.slice();

JSON.stringify — объект/массив → строка. JSON.parse — строка → данные. В localStorage можно хранить только строки.

6. События: как работают клики и формы

6.1. onclick в HTML vs addEventListener в JS

В проекте не используется атрибут onclick="..." в HTML. Все обработчики вешаются в JavaScript — это современный и удобный для поддержки подход.

// Прямая подписка на конкретную кнопку:
checkoutBtn?.addEventListener("click", handleCheckoutClick, { signal });

// Отправка формы CMS (не click, а submit):
cmsForm.addEventListener("submit", onSubmit, { signal });

6.2. Делегирование событий

Один обработчик на родителе ловит клики по динамически созданным кнопкам (карточки каталога перерисовываются через innerHTML).

app.js — каталог (737–744):

function handleProductsGridClick(event) {
    const btn = event.target.closest("button[data-role][data-id]");
    if (!btn || !productsGrid.contains(btn)) return;
    const { role, id: productId } = btn.dataset;
    if (role === "add") addToCart(productId);
    if (role === "match") renderRecommendations(productId, btn);
}
productsGrid.addEventListener("click", handleProductsGridClick, { signal });

Цепочка: пользователь кликает → браузер создаёт объект event → всплытие (bubbling) до productsGrid → closest находит кнопку → читаем data-role и data-id → вызываем нужную функцию.

6.5. AbortController

В bindEvents() все слушатели получают { signal } от одного AbortController. При необходимости можно отписать все обработчики одним вызовом ac.abort().

7. Ключевые алгоритмы (кратко для ответа)

7.1. Фильтрация и пагинация каталога

  1. getFilteredProducts() — поиск + категория + стиль + сортировка.
  2. getCatalogColumns() — 3 / 2 / 1 колонка по ширине экрана (480 / 760 px).
  3. slice для текущей страницы; пустые placeholder-карточки выравнивают сетку.

7.2. Рекомендации «Сочетается с»

Для каждого кандидата считается totalScore: общие стили ×4, подходящая категория +3, близкая цена +1/+2, высокий рейтинг +1, штраф за ту же категорию −5. Берутся лучшие с score ≥ 5, желательно из разных категорий (до 4 штук).

7.3. Корзина

Массив cart: элементы { product, qty }. Доставка бесплатна от 7000 ₽, иначе 490 ₽. Промокоды: NOIR10 (10%), STUDENT15 (15%). Состояние пишется в localStorage после каждого renderCart().

7.4. CMS

Чтение/запись массива в noir-products-v1. ID генерируется по категории (tshirt-6, pants-4). Сброс — удаление ключа из localStorage, снова базовый каталог из data.js.

8. Типичные вопросы на защите

  1. Почему без backend? Учебный frontend; данные в localStorage и статические JSON-подобные структуры в JS.
  2. Чем отличается массив от объекта? Массив — список по индексам; объект — именованные поля (товар, настройки).
  3. Зачем data.js отдельно? Единый источник данных для витрины и админки.
  4. Как работает делегирование? Один listener на контейнере вместо сотен на каждой кнопке после render.
  5. Что такое CSS-переменные в карточке? --img-scale и --img-offset-y для подгонки фото товара.
  6. Адаптивность? Media queries 1150, 760, 480 px; Grid и clamp/minmax.
  7. Библиотеки? jQuery UI — autocomplete; Chart.js — диаграммы; CountUp — анимация цифр на «О проекте».
  8. SEO? meta title/description, robots.txt, sitemap.xml, семантика HTML5, alt у картинок.
  9. Валидация? HTML — validator.w3.org; CSS — jigsaw.w3.org; JS — JSHint + консоль браузера.
Перед защитой: откройте сайт через Live Server, проверьте каталог, корзину, промокод NOIR10, «Сочетается с», CMS (добавить/удалить товар), страницу «О проекте» с графиками. Консоль (F12) должна быть без красных ошибок.
